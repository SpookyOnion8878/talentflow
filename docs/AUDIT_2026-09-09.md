## 1. Executive Summary

TalentFlow adalah platform freelancer/contractor management (B2B SaaS multi-tenant) dalam fase MVP lanjut: 21 model Prisma, RBAC 5 role, siklus kontrak→timesheet→invoice→payment yang **secara domain ternyata jauh lebih disiplin dari biasanya**, plus lapisan AgentOps (engine ReAct, guardrails, DB queue, RAG pgvector) yang sudah jalan end-to-end.

**Kesan utama:** fondasi domain (uang, state transition, tenancy, audit) adalah bagian terkuat dan layak dijadikan kontrak yang dikunci. Masalah terbesar bukan di kode, melainkan di **(a) kejujuran dokumentasi** (README mengklaim fitur yang tidak ada: WebSocket, Stripe, e-sign, export PDF/CSV), **(b) 88 file kerja uncommitted** (risiko kehilangan/inkonsistensi CI), dan **(c) dua bug reliability konkret di job queue agent** (job LOCKED tanpa recovery, cron tanpa `maxDuration`).

Tidak ada alasan untuk rewrite. Perbaikan bersifat targeted.

## 2. Project Understanding

**Tujuan:** mengelola freelancer/contractor end-to-end (data, kontrak, timesheet, invoice, payment, compliance) + lapisan AI agent yang mengamati dan mengusulkan/mengeksekusi aksi operasional dengan manusia di atas siklus finansial.

**Target user:** perusahaan yang memakai 5+ freelancer; role OWNER/ADMIN/MANAGER/FINANCE/VIEWER. Freelancer sendiri **belum punya portal** (model `Freelancer.userId` sudah disiapkan).

**Arsitektur (terverifikasi):**

- Monorepo pnpm + Turborepo: `apps/web` (Next.js 16.3 App Router, React 19, tRPC 11, next-auth 4.24 JWT, Prisma 6.5 + Postgres/pgvector), `packages/`: agents, db, email, ui, utils, validators, eslint-config, typescript-config. Plus `apps/docs` (scaffold create-next-app yang tak tersentuh).
- Data access: tRPC router (`apps/web/lib/trpc/routers/*`, 13 router, ~3.000 LOC) → Prisma langsung, dengan helper domain di `apps/web/lib/domain/` dan `packages/db/src/`.
- Authz: middleware chain `isAuthed` (resolusi Membership aktif) → `requireRole(...)` per endpoint (`apps/web/lib/trpc/server.ts`); redaksi field sensitif via `apps/web/lib/freelancer-access.ts`.
- Scheduler: Vercel Cron 2 endpoint (`vercel.json`) → `/api/cron/agents` (fail-closed auth, `apps/web/lib/cron-auth.ts`).
- UI: ~5.300 LOC TSX, komponen lokal `apps/web/components/*` + Tailwind; polling notifikasi 60 detik.
- CI: GitHub Actions lint → typecheck → test → build → deploy Vercel (main) + preview per PR.

## 3. Apa yang Sudah Baik (KEEP)

1. **Disiplin uang** — `packages/db/src/money.ts`: `Decimal(19,4)`, pembulatan `ROUND_HALF_UP`, `MoneyInvariantError`, `calculationVersion` di Invoice. Ini pola yang kebanyakan MVP langgar; di sini sudah benar + teruji (payment-domain.test 8 tests).
2. **State machine eksplisit** — `packages/db/src/transitions.ts` + `requireInvoiceTransition`/`requireTimesheetTransition`/`requireContractTransition` di router. Illegal transition = 400, bukan data rusak.
3. **Tenancy di schema, bukan hanya di query** — `@@unique([id, companyId])` + FK composite `[freelancerId, companyId]` membuat relasi lintas-perusahaan mustahil di level DB. Index per `companyId` konsisten. (Bukti: `packages/db/prisma/schema.prisma` 14–659.)
4. **Optimistic concurrency yang benar** — pola `updateMany({ where: { id, companyId, status } })` + cek `claimed.count !== 1` → CONFLICT, dan `withSerializableTransaction` dengan retry P2034 (`apps/web/lib/domain/transactions.ts`). Race di settlement invoice sudah ditangani.
5. **Audit trail dalam transaksi yang sama** — `audit()` (`server.ts`) dipanggil dengan `transaction` client, jadi log tidak pernah "lunas di kertas" tanpa datanya.
6. **Redaksi field keuangan** — `freelancer-access.ts`: field bank/tax hanya untuk OWNER/ADMIN/FINANCE, ditulis via `freelancerPublicSelect` + `redactFreelancerSensitiveFields`, ada testnya.
7. **Guardrails agent** — `packages/agents/src/guards/pipeline.ts`: mode PROPOSE/AUTO, threshold nominal, idempotency key (`@@unique([tool, idempotencyKey])`), approval permission terpisah dari permission eksekusi. Data governance default-deny untuk provider eksternal (`providers/data-governance.ts`).
8. **Cron auth fail-closed** — `lib/cron-auth.ts`: secret <32 char = 503 "misconfigured", bukan "allow". Kualitas desain keamanan di atas rata-rata.
9. **Queue dengan SKIP LOCKED** — `packages/agents/src/jobs/queue.ts` raw SQL `FOR UPDATE SKIP LOCKED` mencegah double-claim antar worker serverless.
10. **Seed idempoten + guard** — `packages/db/prisma/seed.ts`: password demo dipaksa eksplisit di luar dev.
11. **Test yang menargetkan hal yang benar** — 135 test lulus; cakupan meliputi payment application, transisi state, cron auth, redaksi akses, tenant isolation tool agent, guard policy. Ini bukan vanity coverage.

## 5. Architecture Review

**Kesimpulan:** arsitektur sudah masuk akal untuk skalanya. Monorepo dengan pemisahan validators/utils/db/email/agents adalah pemisahan yang _benar_ — bukan over-engineering, karena masing-masing punya alasan nyata (validators dipakai lintas client/server, agents butuh isolasi dari Next).

- **Separation of concerns:** baik. Router tRPC tipis-orkestratif; math uang dan transisi state hidup di `@repo/db` (bukan di router, bukan di UI). Copilot context dihitung deterministik (`buildCopilotContext`) sebelum LLM — pola "jangan biarkan LLM menghitung uang" konsisten.
- **Coupling:** `packages/agents` bergantung pada `@repo/db` dan `@repo/email` — sehat. Yang janggal: `react`/`react-dom` ada di dependencies agents padahal 0 import (grep) → sisa, bukan arsitektur.
- **Duplikasi komponen UI:** `packages/ui` (7 komponen) **tidak pernah di-import** oleh siapa pun (grep `@repo/ui` di kode = 0); `apps/web` memakai `apps/web/components/*` yang isinya paralel (status-badge, stat-card, dll. ada di dua tempat). Ini dua sumber kebenaran UI. (Observed)
- **`User.role` vs `Membership.role`:** semua authz memakai Membership.role; `User.role` (enum `UserRole`, default FREELANCER, di-set ADMIN saat register) tidak pernah dipakai untuk keputusan. Model ganda yang menipu pembaca. (Observed)
- **Over-engineering:** tidak ada yang perlu dihapus secara struktural. Abstraction level-nya pas untuk B2B SaaS kecil.
- **Under-engineering (satu-satunya yang materi):** tidak ada service layer untuk alur lintas-entitas — tapi justru `lib/domain/` sudah mengisi peran itu secara minimal. Jangan tambah layer baru.

## 6. Code Quality Review

**Kekuatan:** naming konsisten, router per domain, helper kecil, tidak ada fungsi monster (terbesar ~80 baris di `agents.ts`), superjson, zod di setiap boundary input, error handling tRPC ber-code yang benar (NOT_FOUND/FORBIDDEN/CONFLICT/BAD_REQUEST).

**Temuan:**

1. **[Observed] Cast enum tanpa validasi** — `where.status = input.status as InvoiceStatus` (`invoice.ts:40`, `freelancer.ts:30`, `payment.ts:31`, `timesheet.ts`). Status aneh dari client → Prisma error → 500, bukan 400. **Dampak:** error log berisik + UX jelek. **Fix:** `z.nativeEnum(InvoiceStatus).optional()` di input (pola sudah ada di `agent-inputs.ts`). **Effort:** S. **Priority:** P2.
2. **[Observed] `sortBy` bebas dari client** — `paginationSchema.sortBy: z.string()` → `orderBy: { [sortBy]: sortOrder }` (`freelancer.ts:37`). Dua masalah: (a) kolom tak dikenal → 500; (b) sorting di kolom apapun (termasuk `taxId`) = ordering oracle halus. **Fix:** whitelist `z.enum(["createdAt","firstName",...])`. **Effort:** S. **Priority:** P2.
3. **[Observed] Dead/duplikat kode di `packages/utils`** — `calculateInvoiceTotal` (hardcode pajak 11%, float math!) hanya dipakai test; implementasi kanonik ada di `@repo/db` `calculateInvoiceAmounts`. `calculateBudgetBurnRate` tidak pernah dipakai app. Dua versi matematika uang di repo = bom interpretasi. **Fix:** hapus atau pindahkan ke test fixture. **Effort:** S. **Priority:** P2.
4. **[Observed] `scryptSync` blocking event loop** (`packages/utils/src/index.ts:8,17`) — tiap login/register memblokir worker Node ~50–100ms. Sekarang tidak terasa; di 100 req/s concurrent jadi titik latency. **Fix (saat dibutuhkan):** promisify `scrypt` async. **Priority:** P3. **Effort:** S.
5. **[Observed] Konsistensi kecil:** `freelancer.getById` include `contracts` & `complianceRecords` tanpa `take` (bisa membesar tak terbatas) — Potential, belum masalah di skala demo.
6. **Readability/testability:** baik. Router bisa di-test via `createCaller` (sudah ada factory di `server.ts`) — sayangnya belum ada satu pun test router-level (lihat §13).

## 7. Database Review

**Schema (`packages/db/prisma/schema.prisma`, 21 model, 2 migrasi):**

- **Desain relasi:** FK composite `[entityId, companyId]` + `@@unique([id, companyId])` = tenancy struktural. `onDelete` dipilih sadar: Cascade untuk milik company, **Restrict** untuk Contract pada Invoice/Timesheet (invoice historis tak boleh menghapus kontrak) — keputusan yang benar.
- **Index:** `[companyId]` di semua tabel panas, `[status, runAt]` di agent_jobs (pola claim), `[invoiceId, status]` di payments (query outstanding), `[companyId, createdAt]` di audit_logs. Tidak ada missing index yang saya temukan untuk query yang ada.
- **Query pattern:** list endpoints pakai `Promise.all([findMany, count, groupBy])` — tidak ada N+1 yang terlihat; agregasi ringkasan lewat `groupBy` di DB, bukan JS. `buildCopilotContext` 5 query paralel.
- **Temuan:**
  1. **[Observed] `@@unique([freelancerId, date])` di Timesheet** — satu baris per freelancer per hari lintas proyek/kontrak. Keputusan bisnis yang sah, tapi tidak terdokumentasi; kalau nanti butuh timesheet per-proyek-per-hari, ini migrasi yang mengubah data. Dokumentasikan sebagai constraint produk sekarang (docs/DATABASE.md).
  2. **[Observed] `Payment` tidak punya `companyId`** — tenancy via join ke invoice. Konsisten dan benar; hanya catat agar query future ingat filter via relasi.
  3. **[Potential] `ingestCompanyData` upsert berurutan per chunk + 1 embed call per chunk** (`rag/index.ts`) — O(N) round-trip. Di data perusahaan besar akan lambat; di skala demo tidak terasa. Jangan dioptimasi sekarang.
  4. **[Potential] Pagination offset (`skip/take`)** — fine sampai ratusan ribu baris; keyset pagination nanti jika perlu.
- **Migration hygiene:** migrasi versioned (`20260817000000_baseline`, `..._domain_integrity`) + `pgvector` extension di baseline. Baik. CI **tidak memverifikasi migrasi** (tanpa DB service) — `migration-integrity.test.ts` hanya statik. Tambahkan job Postgres di CI yang menjalankan `migrate deploy` (Effort M, Priority P2).

## 10. Security Review

Kelompok temuan (semua dengan bukti):

**Critical:** tidak ada yang ditemukan. (Tidak ada SQL injection — semua raw SQL pakai `Prisma.sql` parameterized, termasuk vector literal yang di-`Prisma.raw` dari angka; tidak ada `dangerouslySetInnerHTML`; .env tidak ter-track.)

**High:**

- **[Observed] Rate limiter in-memory + IP dari header tanpa gate di register.** `lib/rate-limit.ts` menyimpan bucket di `Map` proses → di Vercel serverless tiap instance punya map sendiri dan reset saat cold start; limit efektif jadi per-instance, bukan global. Dan `getClientIp` (`rate-limit.ts`) percaya `x-forwarded-for` **tanpa syarat**, sementara `lib/auth.ts` sudah lebih benar (gate `TRUSTED_PROXY`). Attack: attacker POST register dengan XFF acak per request → limit per-IP nop. Global (100/j) & per-email (5/j) masih menahan. **Fix:** samakan pola TRUSTED_PROXY di `getClientIp`; terima bahwa limit in-memory hanya "best effort" — upgrade Upstash Redis **hanya jika** platform sudah publik. **Priority:** P2. **Effort:** S (konsistensi) / M (Redis).

**Medium:**

- **[Observed] Akun tanpa verifikasi email.** Register membuat akun berkredensial langsung. Untuk SaaS B2B berisi data bank, verifikasi email (atau minimal kirim welcome) sebelum login pertama layak. **Priority:** P3 sekarang, P1 saat onboarding user nyata.
- **[Observed] Enumerasi email** di login (null → pesan generik: benar) vs register (409 "Email already registered": wajar untuk produk) vs invite (NOT_FOUND: bocor). Konsisten-kan invite.
- **[Observed] Token budget check per step** di loop agent melakukan N query kecil per run — bukan masalah keamanan; catatan efisiensi saja.

**Low:**

- **[Observed]** Session JWT + PrismaAdapter → tabel `sessions` tak terpakai (harmless, dokumentasikan).
- **[Potential]** next-auth 4.24 di atas Next 16 — kombinasi di luar matrix compat resmi next-auth v4 (yang era Next 13/14). Build & type-check lulus; **perilaku runtime harus diuji** (login flow di preview deploy). Unknown sampai diuji. Jangan upgrade ke next-auth v5 sekarang — bukan prioritas.
- **[Observed, positif]** Security headers lengkap di `next.config.js` (X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy, HSTS di prod). Password scrypt + timingSafeEqual. Cron secret sha256 + timing-safe compare + min-length. Ini di atas standar MVP.

## 11. Performance Review

## 12. Reliability Review

- **[Observed] Point terlemah = lifecycle AgentJob** (lihat C2/C3): claim → LOCKED → (crash) → stuck. AgentAction sudah punya recovery (`recoverStaleClaimedActions`, `expireStaleActions`); AgentJob tidak. **Fix:** satu updateMany di cron (`LOCKED` + `createdAt < now-15m` → `PENDING`, attempts+1) — ~10 baris. **Priority:** P1. **Effort:** S.
- **[Observed] Transaksi & rollback:** `withSerializableTransaction` retry P2034 ×3; claim-updateMany di dalam transaksi; audit satu transaksi dengan data. Partial failure di money path ditangani.
- **[Observed] Eksternal:** Resend fallback console (dev) + throw error terformat; Gemini/Ollama error → AgentRun FAILED dengan error tersimpan di DB + steps JSON. Gagal aman.
- **[Observed] Idempotency:** agent actions idempotent via unique key; enqueue dedup harian. Request duplikat di money path dilindungi status-transition claim.
- **[Potential] Restart:** queue di DB (bukan memori) — restart aman _kecuali_ bug C2.

## 15. Feature Review (ringkas per fitur utama)

**Freelancer Management** — Kondisi: solid (CRUD + redaksi PII + guard field-level). Kelebihan: audit per mutasi, test akses. Kekurangan: list-sort bebas, getById include tak terbatas. Saran: pertahankan; perbaiki sortBy whitelist. **KEEP.**
